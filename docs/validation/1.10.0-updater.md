# Updater 1.10.0 — contrôle après publication

17 novembre 2026. Android Studio Emulator API 36, contrôlé uniquement par ADB et UI Automator.

## Résultats

- Les quatre fichiers de la release ont été téléchargés sans authentification, puis comparés aux artefacts locaux par taille et SHA-256.
- Le nouvel updater a téléchargé automatiquement l’APK publique après activation de l’option. Aucun téléchargement manuel n’a été déclenché. Le fichier reçu dans le cache privé correspond exactement à la release.
- La validation native du paquet, de la version, du certificat et du SHA-256 réussit. L’interface affiche [Prête à installer](../screenshots/1.10.0/update-ready.png).
- La demande d’autorisation de source puis le retour à l’application ouvrent correctement la [confirmation Android](../screenshots/1.10.0/update-confirm.png).
- Play Protect demande une analyse, puis bloque l’installation avec `POTENTIALLY_UNWANTED`, `threatType: generic_malware`, « This app may be harmful. ». [Capture](../screenshots/1.10.0/play-protect.png). Le journal ne fournit pas de composant ou comportement précis. Un faux positif n’est pas établi.
- Pour vérifier uniquement le démarrage et la migration des données dans l’émulateur isolé, l’option ponctuelle « Install anyway » a été utilisée. Aucun réglage global de sécurité n’a été désactivé. L’APK release R8 s’installe en 1.10.0 / 1010000, démarre sans exception fatale et conserve les 12 opérations d’historique, comparées intégralement avant/après. [Historique](../screenshots/1.10.0/history-preserved.png).

Le paquet de départ est un build de validation signé avec le certificat habituel, portant le code 1009004 et intégrant le nouvel updater. La 1.9.4 distribuée auparavant n’avait pas d’updater ; son passage à la 1.10 nécessite une installation manuelle.

## Distribution

La release 1.10.0 est passée en **préversion** après ce résultat. Le canal GitHub `/releases/latest` retourne à nouveau **v1.9.4**. L’installation normale sans alerte Play Protect reste **bloquée** ; la validation après exception dans l’émulateur ne remplace pas cette vérification.

Une demande de réexamen a été préparée, mais n’a pas été envoyée. La procédure officielle est décrite dans [les consignes Google Play Protect](https://developers.google.com/android/play-protect/warning-dev-guidance). Aucun téléphone physique n’a été utilisé.
